## Task

Harden SSE tool-call accumulation and stream boundary mapping so incomplete tools, finish reasons, stream errors, and user cancel are faithfully surfaced — never as silent empty “success.”

### 1. Extend `GabClient.ChatCompletionResult`

Add additive fields (defaults so existing call sites compile):

| Field | Type | Meaning |
|-------|------|---------|
| `cancelled` | `Boolean = false` | User cancelled mid-stream |
| `streamError` | `String? = null` | SSE `error` message if stream reported failure but did not throw |
| `incompleteToolCallCount` | `Int = 0` | Builders present at end that could not become full `ToolCall`s (blank id and/or name) |

Keep existing: `content`, `toolCalls`, `finishReason`, `usage`.

**Contract:**

- `finishReason == null` means no non-null string finish reason was seen (distinguish from `"stop"`).
- Do **not** invent `finishReason = "stop"` on cancel or empty stream.
- Complete fragmented tools still appear in `toolCalls` as today.

### 2. Harden `GabSseAccumulator`

**File:** `src/main/kotlin/com/waryway/gab/client/GabSseAccumulator.kt`

- Preserve happy-path fragmented tool accumulation (id/name on first chunk, args fragments later).
- When builders remain incomplete at `toResult()`: **do not silently drop without signal** — exclude them from `toolCalls` (or recover only if safe) and set `incompleteToolCallCount` to the count of incomplete builders. Prefer flagging over inventing fake tool names; optional recovery: if `name` is present and only `id` is blank, you may synthesize a stable id like `call_incomplete_<index>` **and** still count or document — pick one approach and apply consistently.
- Track last SSE error message on the accumulator when `processSseLine` emits `SseEvent.Error` (acceptChunk may not see error-only payloads). Expose via `toResult().streamError` and/or a getter the client can read.
- Keep capturing string `finish_reason` values (`tool_calls`, `stop`, `length`, etc.). Explicit JSON `null` must leave `finishReason` null (not the string `"null"`).
- Prefer not swallowing all failures inside empty `runCatching` without any signal; at minimum, errors that parse as SSE error events must be recorded.

### 3. Map client stream boundary

**File:** `src/main/kotlin/com/waryway/gab/client/GabClient.kt` — `chatCompletionStreaming` (and only result-type / helpers needed).

- On `SseEvent.Error`: **fail the completion** — throw `GabApiException` (or equivalent typed failure) with the server message. Do **not** return empty content + null finish as success after a server error event. If you must return a result instead of throw, set `streamError` non-null and ensure callers cannot treat it as a clean stop; **prefer throw**.
- On user `cancelled()`: break the read loop, return `toResult()` with `cancelled = true`. Do not set `finishReason` to `"stop"`.
- Log finish_reason / tools / cancel / error clearly (existing log style).
- Non-stream `parseChatCompletion`: if you touch it, apply the same finish/tool field defaults; no behavior regressions.

### 4. Do not implement AgentSession policy

Section-03 owns loop exit. Only expose fields; at most a one-line comment if a call site needs a pointer.

### Minimal smoke tests (optional here)

If you touch tests, keep them green; full edge-case suite is **wo-s02-01-02**. Existing three tests in `GabSseAccumulatorTest` must still pass (update assertions if result type gains fields).
