## Task

Fix cloud multi-step **AgentSession** premature exit. The loop must stop only for clear terminal reasons; empty/ambiguous model responses must not silently end work.

### 1. Extract pure loop decision helper

Add a small pure (or near-pure) API under `com.waryway.gab.chat` (e.g. `AgentLoopDecision.kt` or nested types on `AgentSession`) so section-04 / wo-03-02 can unit-test without `Project` / IDE:

Suggested shape (adapt names to repo style):

```kotlin
enum class AgentLoopAction { CONTINUE, RETRY_COMPLETION, TERMINAL_SUCCESS, TERMINAL_ERROR, CANCELLED, MAX_ITERATIONS }

data class AgentLoopDecision(
    val action: AgentLoopAction,
    val reason: String,          // machine-ish: cancel | stop | empty_ambiguous | length | tool_calls | max_iterations | error | ...
    val userMessage: String?     // optional content for final transcript when terminal
)

fun decideAgentLoop(
    cancelled: Boolean,
    content: String?,
    toolCalls: List<*>,          // or List<ToolCall>
    finishReason: String?,
    iteration: Int,
    maxIterations: Int,
    ambiguousRetryCount: Int,
    maxAmbiguousRetries: Int = 2
): AgentLoopDecision
```

### 2. Documented policy (implement exactly)

| Situation | Action |
|-----------|--------|
| `cancelled == true` (before request, after stream, mid-tools) | `CANCELLED` → final content **"Stopped by user."**; log `terminal=cancel` |
| `toolCalls` non-empty | Execute tools then **continue** loop (existing behavior) |
| `finishReason` indicates tool use (`tool_calls`, `function_call`, case-insensitive) even if tools list empty | `RETRY_COMPLETION` or `CONTINUE` with log — do **not** treat as successful short answer; if no tools after retries, `TERMINAL_ERROR` with clear message |
| Non-empty content, no tools, terminal-ish finish (`stop`, `end_turn`, `stop_sequence`, or null with content) | `TERMINAL_SUCCESS`; log `terminal=stop` (or finish reason) |
| Empty content + empty tools + non-terminal/null/blank finish | **Do not** success-break: `RETRY_COMPLETION` up to **2** times; then `TERMINAL_ERROR` with explicit system/user message (e.g. empty/incomplete model response); log reason |
| `finishReason == "length"` | `TERMINAL_SUCCESS` or `TERMINAL_ERROR` with **explicit** note that output hit length limit — not a silent clean stop |
| `finishReason` content_filter / similar | `TERMINAL_ERROR` with visible message |
| `iteration >= maxIterations` | Keep existing explicit max-iter appendix; log `terminal=max_iterations` |
| Hard API exception | Let throw to UI (existing `Error: …`); if you catch inside loop, surface message and log `terminal=error` |

### 3. Rewire `AgentSession.run`

Primary file: `src/main/kotlin/com/waryway/gab/chat/AgentSession.kt`

- Replace the “no tools → break” path with decision helper.
- After `chatCompletion` returns, **re-check cancel** before accepting partial content as success.
- Track `ambiguousRetryCount` for empty/ambiguous retries (same conversation; do not infinite-loop).
- On tool path: if cancel mid-tools, break out with **Stopped by user**, not partial tool-only success.
- If tool executor throws: catch, log, append tool error content or fail loop with visible message — do not die silently.
- **Every** exit path logs via `sessionLog` a terminal line including reason code, e.g.  
  `agent terminal reason=cancel|stop|empty_ambiguous|length|max_iterations|error|tool_rounds…`
- Keep max-iterations user-facing note; keep `(no response)` only when truly terminal empty after policy exhausted (prefer explicit error text over silent empty success).
- Do **not** raise `MAX_ITERATIONS` without documenting why.
- Do **not** redesign conversation manager; do **not** re-implement SSE (section-02).
