## Task

Make **GROK_BUILD chat completions failures actionable** for operators: replace bare `"Error: ${e.message}"` on the shared chat path with a pure helper that maps HTTP/SSE/connect failures to recovery-oriented copy (session/login, proxy unreachable, non-2xx with short body detail). Prefer pure helpers + unit tests; minimal UI wire.

### Context (proven asymmetry)

In `WarywayGabToolWindowPanel` chat catch:

- `LOCAL_LLM` → `LocalLlmSendUx.formatFailure(...)` (actionable)
- Other providers including **GROK_BUILD** → `"Error: ${e.message}"` (generic)

`GabClient` already throws `GabApiException("Chat failed: HTTP ${code}", body)` and SSE errors as `GabApiException("SSE stream error: …")`. Mid-turn **401/403** from cli-chat-proxy currently surface as generic HTTP failures without “run `grok login`” coaching.

Section-01 owns auth.json parsing / session refresh mechanics. Section-04 owns workbench badges / broader recovery strip. This order owns **chat-path failure formatting** for GROK_BUILD (and safe reuse for other cloud chat providers if natural).

### 1. Pure helper

Add a small pure object, preferred locations (pick one; keep package consistent):

- `src/main/kotlin/com/waryway/gab/client/GrokBuildChatFailureUx.kt` **or**
- `src/main/kotlin/com/waryway/gab/ui/GrokBuildChatFailureUx.kt` **or**
- shared name like `ChatStreamFailureUx` if you intentionally support GROK + GROK_BUILD with a `provider` arg

**Suggested API (adjust names as needed):**

```kotlin
fun formatChatFailure(
    error: Throwable?,
    provider: ModelProvider,
    // optional: status extracted from message/body
): String
```

**Mapping (minimum):**

| Condition | Operator-facing guidance (wording flexible; keep short) |
|-----------|--------------------------------------------------------|
| HTTP 401 / 403 (message or body) for GROK_BUILD | Session missing/expired or unauthorized — run `grok login`, then refresh provider/session (do not invent IDE APIs that section-01 will own) |
| Connect refused / timeout / unknown host / network unreachable | cli-chat-proxy / network unreachable — check connectivity; session may still be fine |
| `Chat failed: HTTP NNN` other | Keep status; include short body snippet if available (`GabApiException.body` ≤ ~200 chars, single line) |
| `SSE stream error: …` | Surface server message clearly (not empty) |
| Cancel / interrupt | Do not rewrite as “Chat failed”; leave cancel UX alone if already handled before catch |
| LOCAL_LLM | **Do not steal** `LocalLlmSendUx.formatFailure` — either no-op pass-through or leave LOCAL branch in panel unchanged |

Preserve prefix style consistent with existing UI (`"Error: …"` or match Local’s style). Prefer one clear sentence + optional detail in parentheses.
