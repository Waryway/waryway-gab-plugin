## Task

Implement **pure Grok Build auth/session recovery** and harden session APIs so missing, expired, and HTTP auth failures are distinct and actionable — without IDE restart for post-`grok login` refresh.

### 1. Pure recovery helper (new)

Add a small pure object (preferred name: `com.waryway.gab.client.GrokBuildAuthRecovery`) that:

- Formats **missing session** coaching: run `grok login`, mention auth file path (`GrokBuildAuth.authJsonPath()` or equivalent).
- Formats **expired / near-expired session** coaching: distinct from missing; re-login guidance; optional email if known.
- Maps **auth-class HTTP failures** (status or message containing 401/403, or body hints) to recovery copy that mentions re-login when appropriate.
- Returns `null` / passthrough signal when the failure is **not** auth-class so callers keep non-auth messages.
- Does **not** depend on Swing or IntelliJ UI; unit-testable with plain strings/status codes.

Public surface (adjust names if clearer, document in Worker report):

```kotlin
// Suggested contract — implement equivalently if you rename
fun coachingMissingSession(authPath: String = …): String
fun coachingExpiredSession(email: String? = null, authPath: String = …): String
fun formatAuthFailure(
    message: String?,
    httpStatus: Int? = null,
    body: String? = null
): String?  // null if not auth-class
```

Coordinate with section-04: **single string table** here; section-04 should call this helper rather than invent parallel login copy.

### 2. `GrokBuildAuth` — only if needed

- Keep `readSession()` / `hasUsableSession()` / `Session.isExpired()` (60s skew) as source of truth.
- **Do not rewrite** the auth.json parser unless you find a real parse bug; any parse fix must have a unit test.
- Optional: expose small pure helpers if recovery needs them (e.g. classify session state: missing / expired / usable) without changing read semantics.

### 3. `WarywayGabSettings` session APIs

- Confirm `getApiKey(GROK_BUILD)`: prefer **usable** live session over PasswordSafe override; override only when live session missing/unusable.
- Document override precedence in a short KDoc comment (acceptance: not silent win of stale override over **fresh** live session — current code already prefers live when usable; clarify edge cases).
- Improve or keep `grokBuildSessionSummary()` so missing vs expired remain distinct and actionable (use recovery helper strings where it reduces duplication).
- Add a lightweight **refresh** path for operators after `grok login` without IDE restart:
  - e.g. `refreshGrokBuildSession(): String` that re-reads `auth.json` via `GrokBuildAuth.readSession()` and returns updated summary (no caching of token beyond live read — today reads are live; ensure no accidental memoization is introduced).
- `hasApiKey(GROK_BUILD)` must not treat expired-only tokens as usable unless PasswordSafe override supplies a non-blank key (document behavior).

### 4. Unit tests

- Extend `GrokBuildAuthTest` for expiry skew / usable checks if not already covered.

- Prefer pure tests under `src/test/kotlin/com/waryway/gab/client/`.
